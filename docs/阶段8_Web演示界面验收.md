# 第八阶段：Web演示界面验收

## 1. 目标
第七阶段已获用户验收。复用既有业务服务，以Streamlit提供本机单用户研究演示界面，不执行真实交易。

## 2. 文件
- web_app.py：网页入口，六个功能页面（含使用教程）。
- tests/web/test_web_app.py：6项页面与提交测试。
- pyproject.toml：增加web可选依赖。
- README.md、第七阶段验收状态及本文档。

## 3. 功能
系统总览；已有批次和行情查看；标准CSV上传、清洗预览及accepted导入；已有批次参数化回测与绩效生成；按日选择账户快照、查看价格均线、当日信号和成交；订单和执行明细；绩效曲线、原始报告图及JSON下载；多任务参数与结果表格比较。
默认连接第七阶段manual_sqlite/demo.db，另可选择独立网页SQLite库或启动环境的DATABASE_URL。不会展示连接串。既有任务刷新只读取数据，不重跑业务。再次主动提交回测会创建新任务。

## 4. 命令和验证
安装：`.venv\Scripts\python.exe -I -m pip install -e ".[test,web]"`
运行：`.venv\Scripts\python.exe -I -X utf8 -m streamlit run web_app.py --server.headless=true --browser.gatherUsageStats=false`
测试：`.venv\Scripts\python.exe -I -X utf8 -m pytest -o "pythonpath=src ." -q`
本轮项目Python全量143项通过，退出0，保留2条既有Pandas FutureWarning。新增6项：五页加载；临时库点击提交、绩效保存、刷新不重复建任务，以及有数据的回放与绩效页加载。测试使用临时SQLite，没有写入用户演示库。
实际启动网页并通过内置浏览器读取首页：1个批次、2个任务、2份绩效、484条行情。未对新网页MySQL模式做现场写入测试；未通过浏览器上传真实文件或创建用户库任务。网页截图没有参考设计图，未作逐像素对比。

## 5. 数据与算法
复用import_csv、run_batch_backtest、generate_report、add_indicators和现有SQLAlchemy模型，不修改交易与绩效公式。回放选择已存快照，不重新推演历史；可卖数量和平均成本未存入快照，因此不编造展示。图片通过完整报告内容匹配寻找，避免仅凭不同数据库的同号任务误取图。

## 6. 选择原因
Streamlit与Python分析模块直接衔接；SQLite降低复现成本；表单提交隔离常规界面刷新和写入动作。

## 7. 替代方案
FastAPI和独立前端可用于后续多用户平台；当前先交付本机研究界面。

## 8. 瓶颈
当前整表读取、报告目录扫描和同步计算适合小规模单用户演示；大规模使用需要分页、结果索引与后台任务。

## 9. 面试说明
网页是新的展示和操作入口，业务规则仍由已有服务执行。参数化表单调用回测服务，数据库保存任务和关联结果，页面刷新读取已存结果。测试实际模拟按钮提交，并确认刷新不新增任务。

## 10. 限制
不是公开部署版本，没有账号、权限、任务队列、严格上传大小限制或跨会话提交锁。同步Streamlit提交不能等同于多用户幂等或并发互斥。文件与数据库非原子；回测已提交而报告失败时页面保留任务编号，可在绩效页重试。上传文件写入reports/web/uploads供溯源，不自动删除。重复行情由原有唯一约束拒绝；会话级重复上传提示不代替跨会话约束。网页MySQL模式尚未实测，不以历史CLI MySQL证据替代。未扩展公司行动、多股票、真实撮合或投资有效性研究。
