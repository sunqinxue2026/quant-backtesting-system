# 面试讲解与复现

## 三分钟介绍
这是单股票日频研究型回测系统。CSV适配器保留来源和摘要，清洗器输出互斥的accepted/review/rejected分类；只将accepted与批次原子入库。指标按股票排序分组，双均线比较当前和前一日关系。引擎逐日执行，信号收盘确定、下一有效行情日开盘模拟成交，账户管理T+1、资金、交易单位及成本。执行结果在事务内保存，绩效服务再读快照和成交，生成公式口径明确的指标及图表。

## 本地复现
在项目根目录使用项目Python3.10环境：

```text
.venv\Scripts\python.exe -I -m pip install -e ".[test]"
.venv\Scripts\python.exe -I -X utf8 -m pytest -o "pythonpath=src ." -q
.venv\Scripts\python.exe -I -X utf8 scripts\run_final_demo.py --csv "用户提供的标准CSV" --provenance "用户提供的来源JSON" --output reports/stage7/local
```

CSV至少含symbol,trade_date,open,high,low,close,volume,amount。来源JSON必须含source、symbol、data_as_of（YYYY-MM-DD）、price_type、is_synthetic=false、units（price=CNY,volume=股,amount=CNY）、csv_sha256。不能将合成数据谎报为真实。

默认SQLite，不自动联网，不创建MySQL数据库。MySQL需预先创建专用空库并在本机设置DATABASE_URL，命令增加 --database configured。切勿提交密码或原始行情。运行入口会打印实际task_id、batch_id和database_readback；首次导入新批次，重跑复用已校验批次并创建新任务。不同来源数据发生行情唯一键冲突时不覆盖、不改复权标签规避。

图表与报告在每次独立run目录下的task目录；verification.json记录质量、回读与结果。失败时已提交行情或任务可能保留，不凭退出码判断全部回滚；核对数据库再运行。文件不是数据库事务的一部分。

## 五个回答重点
1. 避免未来数据：滚动窗口和shift(1)，并用追加未来行情不改变历史结果的测试；任意外部策略仍需审计。
2. 交易成本：买价上浮、卖价下调，佣金取比例与最低值较大者，卖方加税；滑点已在价格中，不再扣一次。
3. 事务：flush取得ID但不提交；调用方begin正常结束提交，异常回滚；行情导入与执行保存分属两个事务。
4. 测试：合成行情用于独立手算，真实行情用于输入、驱动、持久化与报告贯通；137项通过不等于收益有效。
5. 实际缺陷：MySQL JSON改变浮点末位，完全相等误报；用严格递归容差并测试真实差异拒绝，金额仍Decimal精确校验。

## 实测结果怎么解释
2023—2024年平安银行484行，SMA5/20、100000元、每次100股、计入配置成本，MySQL任务4/5均最终99644.98元、33笔成交、484快照。仓位比例小，不能将策略-0.35502%与满仓价格基准-15.03268%的差距直接归因为择时能力；另有未处理分红公司行动。期末1笔未平仓，16笔完整交易。没有参数优化、样本外验证或统计显著性结论。

## 诚实说明边界
不支持完整公司行动、交易所日历、停牌涨跌停撮合、多股票、部分平仓、实时交易；来源许可未核实，不分发数据。首次并发报告生成无文件锁，文件与SQL不原子，初始化使用create_all而非增量迁移。下一步工程增强与策略研究应分开立项。
