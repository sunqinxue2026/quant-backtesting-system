# 面试知识与实际代码

更新日期：2026-11-13。面向国内初级量化开发岗位。已有项目讲解见《面试讲解与复现.md》；本文件作为后续重要实现的持续学习索引。

## 1. 清洗终态与原始证据

代码：src/quant_system/cleaning/cleaner.py，MarketDataCleaner.clean。

- 设计理由：不直接dropna后丢弃问题记录，而是保留_raw字段、_source_row、_reason，便于解释数据为何没有进入回测。
- 数据结构与算法：DataFrame列运算；按symbol/trade_date分组识别冲突；duplicated识别完全重复；布尔掩码依次确定互斥终态，末尾检查数量守恒。
- 复杂度：固定字段数量下，数值校验及掩码通常为O(n)，哈希分组与去重通常为期望O(n)，输出排序最坏O(n log n)；多个副本和中间数组占O(n)空间。不是性能基准结论。
- 替代方式：逐行校验易理解但Python循环开销较大；SQL校验适于库内数据但不便保留完整CSV清洗证据。
- 面试追问：同一股票同日两条价格不同怎么办？结合冲突分组代码回答：两条拒绝，不任意覆盖；完全相同才去重。

## 2. 批次与行情原子导入

代码：src/quant_system/data_import.py，import_csv；database.py中的StockDaily唯一约束。

- 设计理由：避免批次已保存、行情只保存一半；相同行情不静默覆盖。
- 数据结构：ORM对象列表、Decimal、CleanResult；factory.begin()管理提交与异常回滚。
- 复杂度：构造n条对象为O(n)时间和空间；总数据库耗时另受索引、驱动与事务实现影响，不能据此保证O(n)实际写入耗时。
- 替代方式：分块导入降低内存但需要设计整批原子性；数据库upsert需要先明确覆盖与来源版本规则。
- 面试追问：flush为何不等于commit？flush发送语句并取得ID，事务仍可回滚；正常退出begin上下文才提交。

## 3. 信号、订单与成交

代码索引：strategies/dual_ma.py、engine/backtest.py、engine/portfolio.py。

回答重点：信号是策略意图，订单是执行请求，成交是实际模拟结果；信号日和执行日分开，账户还要检查资金、数量与T+1。手算11元买100股、8元卖出且零成本，初始10000元最终9700元。

不能宣称自动阻止任意策略使用未来数据。若问引擎复杂度，应先检查当前版本是否在每个交易日重复扫描信号或订单，再给出n个交易日、m个信号下的分析，不能只凭逐日循环就断言全流程O(n)。

## 4. 双数据库验证与浮点差异

代码索引：scripts/run_final_demo.py，report_values_equal。

递归比较字典、列表、类型和值，只给有限浮点末位差异容差，不放宽Decimal账户金额。对包含k个节点的JSON比较，通常O(k)时间、O(d)递归栈空间，d为嵌套深度。替代方案是统一将需要精确比较的数值编码为Decimal字符串，但会改变报告约定，需要确认调用方。
