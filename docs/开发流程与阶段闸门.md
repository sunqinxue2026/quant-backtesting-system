# 开发流程与阶段闸门

项目：Python Quantitative Data Processing and Backtesting System

## 1. 文档目的

本文件规定本项目后续必须采用的七阶段开发流程，避免一次性实现全部功能。它服务于项目学习、面试讲解和可追溯验收。

## 2. 历史执行说明

此前的 Git 历史已经集中提交过多个业务模块，不能被改写成真实的分阶段开发记录：

- `2b89332`：需求书和 README。
- `b019e0d`：一次提交了数据读取、清洗、数据库、指标、策略、回测、绩效、可视化和测试等多个模块。
- 后续提交继续补充回测、数据库、报告和运行修复。
- `7685d4d` 才补充了七阶段验收报告。

因此，现有代码是一个已经集中开发的基础版本；`docs/阶段验收报告.md` 是后补的总结，不能冒充每阶段完成时产生的真实记录。

从本文件提交后开始，所有新增开发严格执行下面的阶段闸门。

## 3. 强制阶段闸门

每个阶段必须依次执行：

1. 阶段开始前，说明本阶段目标、允许修改的文件范围和验收标准。
2. 只实现当前阶段要求，不能提前实现后续阶段业务功能。
3. 为当前阶段编写或更新对应测试。
4. 运行相关命令和测试，保留真实输出。
5. 对照 11 项固定格式完成阶段汇报。
6. 明确当前阶段未完成内容和下一阶段开始前需要确认的事项。
7. 停止开发，等待用户明确确认。
8. 只有收到用户确认后，才进入下一阶段。

“代码已经存在”“前面已经实现”“测试全部通过”都不等于用户确认进入下一阶段。已有代码只可作为当前阶段的背景或待审查对象，不能把后续代码包装成当前阶段新完成的内容。

## 4. 七个阶段及范围

### 第一阶段：环境检查与总体设计

允许内容：Python 3.10、Git、依赖、测试环境检查；总体架构、目录、数据口径、交易时序、数据库设计和开发计划。

禁止内容：实现第二阶段及之后的业务代码，尤其是清洗、指标、策略、回测和绩效实现。

阶段结束条件：完成设计和环境检查报告，未新增后续业务实现，等待用户确认。

### 第二阶段：行情读取与数据清洗

允许内容：CSV 数据源接口、行情读取、字段和类型标准化、质量报告、清洗单元测试和明确标记的测试数据。

禁止内容：数据库持久化、指标、策略、回测和绩效功能。

阶段结束条件：清洗流程可运行，测试通过，按固定格式汇报，等待确认。

### 第三阶段：数据库设计与数据访问层

允许内容：SQLAlchemy 模型、初始化 SQL、环境变量配置、批量写入和查询、事务测试。

禁止内容：新增策略规则和回测撮合逻辑。

阶段结束条件：数据库层测试通过，SQLite 本地验证完成；MySQL 未验证时必须如实标明，等待确认。

### 第四阶段：技术指标与双均线策略

允许内容：收益率、SMA、EMA、波动率、成交量均线和双均线信号测试。

禁止内容：修改订单成交、资金和持仓逻辑。

阶段结束条件：指标和信号测试通过，解释未来函数防范，等待确认。

### 第五阶段：回测引擎与账户管理

允许内容：订单、成交、持仓、现金、费用、滑点、T+1、下一交易日执行和确定性回测测试。

禁止内容：新增与本阶段无关的数据源或可视化功能。

阶段结束条件：账户变化可手工核算，回测测试通过，等待确认。

### 第六阶段：绩效指标与可视化

允许内容：绩效公式、净值、回撤、信号图、基准对比图和报告输出。

禁止内容：借助图表掩盖前一阶段的引擎错误；发现引擎错误必须记录并回到对应阶段修复。

阶段结束条件：指标边界测试和图表生成验证通过，等待确认。

### 第七阶段：测试、缺陷修复与文档

允许内容：全量回归、缺陷修复、端到端演示、README、面试说明和最终验收。

禁止内容：把未实现功能写成已支持功能。

阶段结束条件：全量测试、演示、文档和已知限制完成最终验收。

## 5. 每阶段固定输出格式

每个阶段结束时必须逐项输出以下内容，不能用一份总报告代替：

1. 本阶段目标。
2. 新增或修改的文件。
3. 已实现的功能。
4. 运行过的命令和测试结果。
5. 核心数据结构、算法和公式。
6. 采用该方案的原因。
7. 可选替代方案。
8. 性能瓶颈和后续优化方向。
9. 面试官可能追问的问题及回答思路。
10. 尚未完成的内容。
11. 下一阶段开始前需要确认的事项。

第 4 项必须来自本阶段实际运行记录。第 10 项必须保留真实限制。第 11 项汇报后，必须停止等待用户确认。

## 6. 阶段确认规则

只有以下明确表达才视为进入下一阶段的确认：

- “确认进入第二阶段”。
- “开始下一阶段”。
- “按这个阶段继续”。

如果用户只提出问题、要求解释、要求查看结果或指出缺陷，不视为进入下一阶段。修复当前阶段缺陷时，仍然停留在当前阶段；修复完成后重新按 11 项格式汇报。

## 7. Git 提交规则

每个阶段原则上使用独立提交，提交说明包含阶段编号和阶段名称。例如：

```text
阶段2：完成CSV行情读取与数据清洗
```

提交前检查 `git status --short`，提交后记录提交号、测试命令和结果。未经过用户确认的下一阶段文件不得混入当前阶段提交。
