# 技术决策记录

更新日期：2026-11-13。以下是现有实现的整理，不代表新增技术决策获批。

## TD-001 SQLite默认演示，保留MySQL

SQLite降低本地运行和临时测试成本，MySQL用于真实驱动、精度、约束及事务集成验证。SQLAlchemy统一模型与会话，但不抹平数据库行为差异。SQLite可通过Navicat等支持它的客户端查看，不以图形界面能力作为强制使用MySQL的理由。

## TD-002 行情清洗采用互斥终态

cleaning/cleaner.py保留原始字段和来源行号，将数据划为accepted、review、rejected或duplicate_removed；校验数量守恒。只有accepted入库。冲突重复不任意保留某一条，零成交进入review，不凭空补行情。

## TD-003 交易时序与金额

engine/backtest.py按行情日期推进，收盘信号后下一行情日尝试开盘执行；Portfolio维护现金、持仓和可卖数量。金额采用Decimal，成本显式配置；滑点体现在成交价格中，不重复扣费。未建模完整停牌、涨跌停和公司行动，不宣称真实撮合。

## TD-004 事务边界

data_import.py使用factory.begin()将批次与行情一起提交；回测结果由编排层事务保存配置、任务和执行明细。行情导入与回测属于不同事务。flush取得ID但不是commit。报告文件与数据库非原子提交，失败可能保留文件。

## TD-005 可重复演示与回读

scripts/run_final_demo.py校验来源摘要，验证后复用行情批次，每次创建新任务。JSON回读使用结构和类型检查，有限浮点允许rel_tol=1e-12、abs_tol=1e-14；交易金额和快照仍按Decimal核对。文件摘要能证明文件对应关系，不能独立证明行情真实性。

## TD-006 Web复用业务层

web_app.py以Streamlit提供单用户演示界面，复用清洗、回测与报告服务。普通刷新不应重复提交任务；此项不等于已实现跨会话并发锁。保留CLI入口及自动化测试。

## 待负责人确认的审查问题（未修复）

1. 自动仓位上界与按分舍入的estimate口径不同：1000元、价格10.000001、零费用时可能少买一手。建议同口径扩展上界再二分。
2. 卖出所得不足最低佣金且余额为零时现金可能为负。建议拒绝导致负现金的卖出，需确认业务规则。
3. 最低佣金5.005与初始本金0.001等分以下输入缺少统一处理。需决定拒绝或ROUND_HALF_EVEN规范化，并确保执行与持久化本金一致。
4. 同任务首次并发报告可能覆盖文件；需独立设计任务认领及文件发布，不仅依赖结果唯一键。
5. 网页上传预览持续落盘，建议临时生命周期及配额。当前仅限可信本机单用户。
