## 3. 已实现的功能

### 技术指标

- 日收益率。
- 累计收益率。
- SMA 短周期和长周期均线。
- EMA 短周期和长周期均线。
- 日频滚动波动率。
- 年化滚动波动率，默认使用 252 个交易日年化。
- 成交量移动平均线。
- 多股票按 `symbol` 分组计算。
- 窗口不足时保留缺失值，不使用 0 填充。
- 输入 DataFrame 深拷贝，避免原地修改调用方数据。
- 窗口参数、年化交易日参数和必需字段校验。

### 双均线策略

- 短均线上穿长均线生成 `BUY`。
- 短均线下穿长均线生成 `SELL`。
- 前一日均线相等后发生上穿或下穿时可以产生信号。
- 均线窗口不足时不产生信号。
- 输出信号日期、股票代码、方向、短均线值和长均线值。
- 信号数据不包含成交日期，避免与第五阶段订单执行混淆。

### 信号持久化

- `MarketDataRepository.add_signal_batch()` 批量写入信号。
- `MarketDataRepository.query_signals()` 按任务和信号日期查询。
- 复用第三阶段已有的 `backtest_signal` 表。
- 使用 `task_id + signal_date` 唯一约束阻止同一任务重复保存同一天信号。
- 信号写入沿用调用方事务边界，重复冲突时整批回滚。

## 5. 核心数据结构、算法和公式

### 日收益率

```text
daily_return_t = close_t / close_(t-1) - 1
```

第一条记录没有前一日收盘价，因此保留为缺失值。

### 累计收益率

```text
cumulative_return_t = close_t / close_first - 1
```

第一版假设价格序列已经经过统一口径处理，累计收益率直接基于收盘价计算。

### SMA

```text
SMA_n(t) = 最近 n 个收盘价的算术平均值
```

窗口不足 `n` 个有效值时保留缺失值。

### EMA

```text
EMA_t = α × close_t + (1 - α) × EMA_(t-1)
α = 2 / (n + 1)
```

代码使用 Pandas `ewm(adjust=False)`，并要求满足最小窗口后才输出有效 EMA。

### 滚动波动率

```text
rolling_volatility_n(t) = 最近 n 个日收益率的样本标准差
annualized = rolling_volatility_n(t) × √252
```

### 双均线交叉

买入条件：

```text
sma_short[t] > sma_long[t]
且 sma_short[t-1] <= sma_long[t-1]
```

卖出条件：

```text
sma_short[t] < sma_long[t]
且 sma_short[t-1] >= sma_long[t-1]
```

策略只使用当前行和前一行均线，不使用未来行。`signal_date` 表示收盘后信号产生日期；`execute_date` 尚未在本阶段生成。

## 6. 采用该方案的原因

- Pandas 的滚动窗口、指数加权和分组运算适合日频时间序列，代码可读且便于手工复核。
- 指标与策略分离，指标可以被多种策略复用，策略也不需要耦合数据读取或数据库细节。
- 使用缺失值表达窗口不足，避免将 0 错当成均线或收益率，减少虚假信号。
- 使用 `symbol` 分组，避免多只股票拼接后发生跨股票收益率和均线污染。
- 将信号日期与成交日期分开，为第五阶段的次日开盘执行和未来函数防范保留清晰边界。
- Repository 只负责持久化，事务由调用方控制，便于单元测试和后续回测任务编排。

## 7. 可选替代方案

- 使用 NumPy 数组手动计算均线，减少 Pandas 开销，但可读性和缺失值处理会变差。
- 使用 TA-Lib 等第三方指标库，但会增加本地安装依赖，核心公式不够透明，不利于面试讲解。
- 使用数据库窗口函数计算指标，适合部分报表场景，但策略研究的迭代效率低，且不同数据库方言存在差异。
- 使用事件驱动策略逐行生成信号，适合实时系统；当前研究型日频第一版使用向量化指标加交叉判断更容易测试。
- 使用 Alembic 管理信号表结构迁移；当前阶段复用第三阶段已经存在的表结构，迁移工具属于后续工程化增强。

## 8. 性能瓶颈和后续优化方向

当前实现会复制 DataFrame，并对每个股票执行分组滚动计算，适合本项目的单股票和小规模研究数据。

数据量扩大后可能出现：

- 大型 DataFrame 复制带来内存压力。
- 多股票分组滚动计算耗时增加。
- 生成大量信号对象和 ORM 对象时写入速度下降。
- 指标重复计算导致研究迭代变慢。

后续可以：

- 使用分块读取和分组缓存。
- 对指标结果做数据版本和参数缓存。
- 对大批量信号使用批量 SQL 或数据库 `executemany`。
- 用 Parquet、Polars 或 NumPy 数组优化大规模离线计算。
- 增加基准测试后再决定优化方向，不提前声称性能提升比例。

## 9. 面试官可能追问的问题及回答思路

### 为什么窗口不足不填 0？

0 不是“没有足够历史数据”的真实含义。填 0 会制造虚假均线交叉和交易信号，所以保留缺失值，在策略中忽略不完整的交叉条件。

### 如何避免未来函数？

信号日只使用当天及之前的指标，交叉条件只比较当前行和前一行；代码不使用 `shift(-1)`，也不对未来数据做回填。成交时间留给下一阶段按下一交易日开盘处理。

### 为什么指标计算和策略逻辑分离？

指标是可复用的数值计算层，策略是业务规则层。分离后可以单独验证 SMA、EMA 是否正确，也可以让不同策略复用同一组指标。

### 为什么要按股票分组计算？

如果多只股票直接拼接计算，某只股票第一天可能会与另一只股票最后一天计算收益率，均线窗口也会跨股票污染。按 `symbol` 分组可以保持每只股票的时间序列独立。

### 信号日期和成交日期为什么分开？

收盘后才能确定交叉信号，不能假设使用当天收盘价成交。第四阶段只生成 `signal_date`，第五阶段再根据交易日序列生成下一交易日订单和成交日期。

### 测试通过是否证明策略有效？

不能。测试只能证明实现符合定义的公式和规则，不能证明策略具有样本外收益，也不能替代对数据偏差、交易成本和真实可成交性的研究。
